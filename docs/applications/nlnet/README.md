## Rules that bind this proposal

- Grants are "primarily for technical development". Software, hardware and content must be released under open licences and apply open standards. ALEA is MIT.
- "Proposals and projects should be made by humans, not AI." The form has a disclosure: did you use generative AI in writing the proposal, and does the codebase contain AI-generated code. **Answer the second question yes.** ALEA was built with Claude Code. Describe it in the 1,000-character box.
- EU-supported funds need a European dimension. The open call does not, and this application goes to the general fund. If the form asks about it, say the applicant is in Kenya and the work has no EU-programme dependency.
- Character limits: summary 1,000; budget 4,000; comparison 4,000; technical challenges 4,000; ecosystem 2,000; background 2,000; other funding 1,000.

## Fit, and the risk

NLnet funds open internet infrastructure and commons technology. ALEA as "an energy planning model" is a stretch. The honest fit is narrower: an open, cited, dimension-checked parameter-graph library and dataset (the PRG), with the Kenya model as its first and only user. The draft therefore leads with the library and the open data, and names the model as the proof. Expect a reviewer to ask why this is internet infrastructure; the answer in the draft is reproducibility and public auditability of models that governments use to decide on grid investment, which is a commons problem. If you think that argument is weak, do not stretch it; apply to the Catalyst Fund and Mozilla instead.
